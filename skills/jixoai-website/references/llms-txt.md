# llms.txt export — the AI-facing layer

jixoai sites are AI-friendly by design, so every site ships the export
natively: after the final static build, one pass scans the published HTML
and writes `llms.txt` (llmstxt.org proposal v2), `llms-full.txt`, and a
`.md` mirror beside every page. Canonical implementation:
`jixoai-labs/ui` → `registry/files/llms-txt/llms-txt.mjs`, distributed as
the registry item `llms-txt` (`npx jixoai-ui add llms-txt` installs
`vite-plugins/llms-txt.mjs`).

The generator NEVER takes over the routing layer — it consumes the final
artifact that agents will actually fetch.

## Law (binding, from the 2026-08-22 ZCode+Codex design review)

- **Scan the final dist.** Orchestrated builds (unipty-style scripts that
  inject artifacts after vite) call the core as their LAST step; only a
  plain `vite build` site uses the plugin adapter.
- **One generation point per site.** Never wire the vite plugin AND an
  orchestrator call — double generation must not happen.
- **Declared outputs only.** `llms.txt`, `llms-full.txt`, `<page>.md`
  mirrors. Nothing deleted; robots.txt / sitemap.xml never touched.
- **Absolute URLs** (the ecosystem's most common llms.txt defect is
  relative paths — the file is read detached from any page).
  `linkStyle: 'root-relative'` exists only for preview builds.
- **Hand-written .md is sacred.** Generated mirrors start with a
  provenance marker (`<!-- generated by jixoai llms-txt … -->`); a
  conflicting file aborts the run.
- **Byte-deterministic.** Same dist in, same bytes out; re-runs converge.
- **llms-full.txt is capped** (`full.maxBytes`, default 10 MB); over the
  cap the run FAILS naming the size — never silently truncate. It is a
  community extension, not part of the llmstxt.org proposal.

## Integration shapes

### Plain `vite build` sites (openspecui pattern)

```ts
// vite.config.ts
import { llmsTxt } from './vite-plugins/llms-txt.mjs';

export default {
  plugins: [
    sveltekit(),
    llmsTxt({
      distDir: 'dist',
      siteUrl: 'https://openspecui.jixoai.com',
      title: 'OpenSpecUI',
      summary: '…agent-facing one-liner…',
    }),
  ],
};
```

The plugin runs exactly once — in the SSR build's `closeBundle`, after
SvelteKit's adapter (enforce `pre`, sequential closeBundle) has written
the final dist. Guard: it no-ops outside `command === 'build' &&
build.ssr` (client build, dev server).

### Orchestrated sites (unipty / ui pattern)

Call the core as the LAST build step, on the FINAL output directory —
after artifact copies, stylesheet publishing, and CNAME gating:

```js
import { generateLlmsTxt } from './vite-plugins/llms-txt.mjs';

const report = generateLlmsTxt(distDir, config); // throws on conflicts/caps
```

`distDir` for the plugin is resolved against the vite root (default
`dist`).

## Config schema

| Field | Default | Notes |
| ----- | ------- | ----- |
| `siteUrl` | required | Absolute URL; base paths (github.io/repos) preserved |
| `title` / `summary` | — | Index H1 and blockquote |
| `include` | `['**/*.html']` | Globs; `**` spans separators |
| `exclude` | `['404.html']` | Add internal playgrounds / render farms |
| `sections` | none | `[{ title, include: [globs] }]`, first match wins; unmatched → `Pages` |
| `linkStyle` | `'absolute'` | or `'root-relative'` |
| `perPageMarkdown` | `true` | `.md` mirrors; index links point at them |
| `full` | `{ enabled: true, maxBytes: 10_000_000 }` | `enabled: false` skips llms-full.txt — it never deletes a stale one (declared-outputs-only law); remove it in your own pipeline |
| `locale` | none | `{ segments: ['en','zh'], default: 'en' }` — see below |
| `additionalEntries` | none | `[{ optional, name, url, description }]` e.g. a machine-readable registry index under `## Optional` |

## i18n

For `[lang=locale]` sites, set `locale: { segments, default }`. Every
segment gets its own stable `<seg>/llms.txt`; the root `llms.txt` repeats
the default locale plus an "Other languages" section. All locales get
per-page `.md` mirrors; `llms-full.txt` follows the default locale only
(a mixed-language dump defeats retrieval).

## Extraction & fidelity

- Content root: `<main>` (fallback `<body>`); chrome stripped by PLATFORM
  semantics, never site-private class names: `script/style/nav/header/
  footer/aside/form/svg/...` subtrees, `button` controls (labels are
  noise — the semantics live in prose and usage code), `aria-hidden`
  decorative spans, and `inert` collapsed panels (e.g. the code drawer —
  its content duplicates the page's open sections). Hydration payloads
  and chrome never leak.
- Whitelist stack-based tokenizer (not regex chains): headings, lists
  (tight, nested), tables (GFM; colspan/rowspan degrades to rows instead
  of a wrong grid), fenced code with language detection
  (`data-lang` / `language-*` / `lang-*`; shiki line-spans keep their
  newlines), entity decoding, safe links only (`javascript:` and friends
  drop to plain text; `data:` images degrade to alt).
- `noindex` pages are skipped automatically (report lists them).

## Verification (site checklist)

- [ ] `dist/llms.txt` exists; H1 + blockquote + H2 sections; every link
      absolute and resolving (spot-check `.md` mirrors exist).
- [ ] Excluded/internal pages have no `.md` mirror.
- [ ] Re-running the generation is byte-identical (idempotent).
- [ ] `llms-full.txt` under the cap; page bodies separated by `---` with
      URL headers.
- [ ] i18n sites: per-locale indexes exist; root points at the default.
- [ ] Existing robots.txt / sitemap / post-build artifacts untouched.
