## wasm 资产（决定 tree-sitter 走 npm-asset channel）

`npm pack` 后 `tar -tzf` 实测（探测目录 /tmp/ts-wasm-probe）：

| 包 | 版本 | 关键产物 |
|---|---|---|
| web-tree-sitter | 0.27.0 | `web-tree-sitter.wasm`（根）+ `web-tree-sitter.d.ts` + `debug/web-tree-sitter.wasm` |
| tree-sitter-typescript | 0.23.2 | `tree-sitter-typescript.wasm` + `tree-sitter-tsx.wasm` + `queries/highlights.scm` |
| tree-sitter-javascript | 0.23.1 | `tree-sitter-javascript.wasm` + `queries/highlights.scm` + `queries/highlights-jsx.scm` |

结论：核心 wasm、语法 wasm、query 源码全部随 npm 包发行——供应链交给
lockfile，无需 ghostty 式 pin 工作流。ABI 注意：grammar 0.23.x wasm
需在 web-tree-sitter 0.27 的 ABI 支持窗口内，测试必须真实加载断言。

## highlight.js（决定 curated 集与 reject 清单）

highlight.js@11.12.0 tarball 实测：

- `lib/core.js` + `lib/core.d.ts` 存在（core+选择性注册通道可用）
- **无** `lib/languages/{tsx,jsx,svelte,vue}.js`（grep 空结果）

bash / markdown / yaml；tsx/jsx/svelte/vue → reject 带提示（改用 shiki backend）。

## sugar-high（2.x 现实修正）

sugar-high@2.3.1 tarball 实测：

- `highlight(code, {lang})` 直接返回 HTML 字符串（README："returns HTML
  without requiring a DOM"）
- `LanguageName` 为 29 个 canonical 名的封闭联合类型：javascript,
  typescript, css, python, c, go, java, rust, json, diff, shell, cpp,
  csharp, sql, html, yaml, markdown, plaintext, ruby, kotlin, swift, php,
  toml, powershell, dockerfile, graphql, hcl, zig, lua
- token 类型：identifier / keyword / string / class / property / entity /
  jsxliterals / sign / comment / break / space
- 体积（其 README 自标基准，**测于 2.2.2**，非 2.3.1 实测——归因按此
  口径引用）：TS 场景 min 9.90 KiB / gzip 4.35 KiB，对照 prism 14.63 /
  5.47、hljs 29.54 / 11.12
- 语言别名策略：ts→typescript、js/jsx→javascript（JSX 为其 JS 语法的
  原生方言）、sh→shell、md→markdown、yml→yaml、htm→html；
  **tsx 不设别名** → reject 带提示（改用 shiki backend）

## fresh worktree 引导序列（工具链事实）

1. 根 `pnpm install`（需先 `pnpm approve-builds esbuild --yes`——
   pnpm-workspace.yaml 的 allowBuilds 占位符置 true，已随分支落盘）
2. `apps/www` 内 **npm ci**（apps/www 不在 pnpm workspace，自带 package-lock）
3. `packages/vite-plugin` 内 `pnpm build`（tsdown 产物不进 git，vite.config
   依赖其 dist 入口）
4. `apps/www` 内 **npx svelte-kit sync**（tsconfig extends 生成的
   .svelte-kit/tsconfig.json；缺失时 rolldown 依赖优化器以
   "Tsconfig not found" 失败，症状为 `Could not resolve 'node:module'
   in \0rolldown/runtime.js`——已实测定位，勿再误诊为 conditions 问题）

按此序列后 `npx vitest run test/code-card-backend.spec.ts` 原配置 18/18 绿。
