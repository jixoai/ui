## Why

Owner ruling (2026-08-26): the repo maintains TWO hand-aligned
implementations of the same design law — jx-pure (the zero-JS CSS
face) and the registry components (tailwindcss+DOM recompositions of
the same look, e.g. native-select re-deriving the jx-select paint by
hand in utility strings). The upgrade uses tailwindcss `@apply` to
project jx-pure's styles DIRECTLY into the registry at 1:1 component
granularity (one jx-pure law ⇔ one registry component), eliminating
the divergence by standard, and lands the toggle-group as a NATIVE
label+radio / label+checkbox control (single/multiple).

Design settled with Codex (gpt-5.6-terra xhigh, 2026-08-27 session
`codex-jx-pure-fusion`, 23m analysis): **verdict = "A-verified"**
(dual-source renderers under a single spec + computed-style parity
gates; daisyUI-style single-source codegen REJECTED with documented
re-entry conditions), toggle-group = native radio/checkbox, no
re-press clear, jx-form-field bridge deleted. Codex fact-corrections
absorbed: only 12/77 UI items depend on @jixoai/jx-pure (not
"most"); registry components cannot drop the Part A classes until a
shared contract layer exists; named-theme `@apply` fails without a
Tailwind context (verified empirically), arbitrary utilities compile.

## What Changes

1. **NEW spec `native-contract`** — the law source: the native
   vocabulary table (law ⇔ component ⇔ DOM contract ⇔ state matrix),
   the @apply mirror law with its hard boundary (context-free +
   arbitrary utilities only; named theme utilities banned in folder
   css), the parity gate contract, and the toggle-group native DOM
   contract (six Codex additions included: reset, name, value order,
   required, uniqueness, event API split).
2. **Part A extraction** — `registry/files/theme/jx-native-contract.css`
   as a GENERATED byte-exact extract of jx-pure.css Part A
   (script + drift gate); new `registry:lib` item
   `@jixoai/jx-native-contract`; the 12 UI items switch their
   dependency from the full 2006-line face to the contract. jx-pure.css
   itself stays hand-written canonical (bytes unchanged except the
   laws below).
3. **toggle-group goes native** — root renders label+input pairs
   (radio for single / checkbox for multiple), native keyboard
   (arrow-walk, one tab stop for radio), native FormData via name
   (bridge deleted), DOM-checked as uncontrolled truth. jx-pure.css
   Part A gains the `.jx-tgroup` opt-in law (joined-edge + `:has()`
   active paint) so Tier-0 paints the same DOM contract classlessly.
4. **@apply mirror migration for the native family** — input,
   textarea, native-select, checkbox, radio, toggle, toggle-group:
   static component paint moves from inline utility strings into
   per-folder mirror sheets (`.jx-*` rules in `@layer components`
   `:where()`), rule-by-rule mirroring the jx-pure law; state
   machines stay unlayered `:where()` bare CSS (carve-out law).
5. **Part B density adoption** — jx-pure.css Part B's hard-coded
   `2.5rem` rows move to the `--jx-*` alias interface, the `.jx-pure`
   scope root gains `font-size: var(--jx-text)` / `line-height` per
   the already-merged spec claim; verify-jx-pure.mjs asserts derived
   numbers instead of literals (resolving the known spec/file drift
   in the direction the spec already mandates).
6. **Parity gates** — `verify-native-parity.mjs` (computed-style
   parity on shared DOM fixtures across the two renderers, state
   matrix included, CSS-value normalization) + screenshot oracle for
   pseudo builds; existing verify:mirror / gzip budget / parity spec
   stay green throughout.

## Impact

- Specs delta'd: native-contract (ADDED), jx-pure, component-authoring,
  css-architecture, registry.
- Breaking: toggle-group loses re-press-clear (single) and the
  bridge payload (newline-joined) — native FormData semantics replace
  both; onchange splits into native event forwarding + onValueChange.
- Non-breaking by construction: jx-pure.css consumers (bytes preserved
  modulo the Part B density sweep — a spec-mandated fix).
