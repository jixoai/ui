8 frozen families in every configuration, differing ONLY in styling-
engine wiring. The registry payload MECHANISM (shadcn add, source-copy,
payload parity) is already proven for the TW form by verify:shadcn-add
and is engine-invariant — it is NOT re-proven here.

Payload trims, disclosed (apply to the TW form's copied closure, for
parity with the corpus payload which ships none of these in ANY

  `DEFAULT_SHIKI_BACKEND` value-import is replaced by a local
  plain-text null backend (same `HighlightBackend` seam; the corpus
  code-card floor ships no highlight engine).
- `tw-baseline/src/lib/jixoai.css`: the two `@fontsource*` `@import`s
  commented out (font files are site delivery; no config ships them).

## 8. Anomalies + friction log

1. **Class-name nondeterminism across build environments** — arch-a
   and arch-b built the SAME corpus payload with the SAME engine
   options into byte-equal-size css with DIFFERENT hashed class
   names. Root not chased (out of D3 scope); flagged for D1's
   "class determinism kernel-build vs consumer-build" row.
2. **C's r4 cold 5.40s outlier** (swap pressure 17.5GB; also 3.91s in
   r5) — nearest-rank p95 absorbs it; C still passes at +12.7%.
   TW's own spread (3.36–4.79s) shows the same machine noise.
3. **vite 8 config-hook plugin injection does not work** (probed:
   plugins returned from `config()` are dropped) — the stub instead
   derives serve/build from NODE_ENV, probed reliable on this pin set
   (`vite build` → production, `vite dev` → development at
   config-eval time). The spike-report's "vite never sets NODE_ENV"
   line should be footnoted (it did not hold under vite 8.3.0's CLI
   here).
4. **npm `file:` dir deps are symlinked** and their dependency
   closure does not resolve — arch-b uses an `npm pack` tarball (the
   realistic published shape; command in §1/README).
5. **npm dry-run exposes no tarball byte totals** (11.19.0) —
   limitation recorded; du median is the F5 byte measurement.
6. **Payload-parity trims** (shiki backend, fontsource) were MY call
   under the 载荷恒定 scope rule — without them, TW's tree would
   carry a multi-MB shiki closure no StyleX config ships, contaminating
   bytes Δ in StyleX's favor. Gate 2 may re-derive with the trims
   reverted to confirm the direction of the bias.
7. The 8 TW-family closure is 44 files (script-computed transitive
   import closure, `$lib/`→relative rewrites verified by residual-
   alias grep); `@ui/press-button.svelte` appears only inside a
   doc-comment (press-button.svelte:38) — left verbatim.
